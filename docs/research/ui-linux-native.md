# Замеры UI на нативном Linux (условие 5 ADR-003)

Перемер GPUI на нативной Linux-системе, который [ADR-003](../adr/0003-ui-toolkit.md) (условие 5) требует до приёмки E7. Дополняет раздел «Результаты: Linux (WSLg)» в [отчёте спайка](ui-spike.md). Сырые данные прототипа: `spikes/ui/results/linux-x11-intel-uhd-60hz.jsonl`.

Дата: 27.09.2026. Коммит: `2c55fcb` (ветка `staging`) плюс незакоммиченные правки E7 в `kumiko-ui` (дерево, вкладки).

## Стенд

| | |
|---|---|
| Машина | ASUS ROG Strix G16: Intel Raptor Lake-S UHD (встроенная) + NVIDIA RTX 4060 Max-Q (драйвер 580.159.03) |
| ОС | Ubuntu 24.04.4 LTS, ядро 6.17.0-22, Mesa 25.2.8 |
| Сессия | GNOME 46, **X11** (Wayland — только вложенный `gnome-shell --nested`, см. ниже) |
| Экран | 1920×1200, 60 Гц (панель умеет 165 Гц, но в сессии выбрано 60) |
| IME | IBus 1.5.29, `XMODIFIERS=@im=ibus` |
| Сборка | rustc 1.98.1, release, GPUI 0.2.2 |
| ФС | Репозиторий лежит на NTFS через FUSE (`/media/.../Work`, `fuseblk`); для сравнения копия без `target/` на ext4 |

Какой GPU рисует: по умолчанию **Intel** (процесса нет в `nvidia-smi`), но загрузчик Vulkan при перечислении адаптеров загружает все ICD, включая библиотеки NVIDIA. Поэтому замеры сняты в двух вариантах: по умолчанию и с `VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/intel_icd.json` (только Intel).

## Методика

- **Прототип спайка** `spikes/ui/gpui-proto`: режимы `SPIKE_BENCH=start|scroll|type`, `SPIKE_T0` задаётся перед запуском (как в `run-windows.ps1`), нагрузка из `workload` (10 000 строк с подсветкой, дерево из 925 узлов).
- **Workbench** `target/release/kumiko [FOLDER]` (E7): своего таймстемпа первого кадра у него пока нет. Старт считается от запуска до появления окна `"Kumiko"` в `xwininfo -root -tree` (опрос каждые 5 мс). Это время до map окна, а не до первого кадра.
- **RAM в покое**: `VmRSS`, `RssAnon`, `RssFile` из `/proc/<pid>/status` через 30 с после старта (бюджет раздела 23).
- **CPU в покое**: `utime+stime` из `/proc/<pid>/stat` за 60 с после первых 30 с (бюджет раздела 23: < 1 %).
- **AT-SPI**: скрипт на `gi.repository.Atspi` обходит дерево приложения на шине доступности и считает роли. Для этого временно включалась `org.gnome.desktop.interface toolkit-accessibility` (потом возвращена в `false`).

## Подробности и находки

### 1. Разовые подвисания кадров на X11 (GPUI)

В устойчивом режиме прокрутка идёт ровно 60 fps (p95 16,8 мс). Но почти в каждом втором прогоне есть одно подвисание:
- обычно 0,2–5,4 с (`max` в `frame_ms`), из-за него `mean` падает до 39–52 fps;
- в 5 из ~45 прогонов (1 в `start`, 4 в `scroll`) окно совсем перестало получать кадры (обрыв по таймауту 30–60 с), один раз — подвисание 32 с;
- с ICD только Intel случается чаще, чем по умолчанию;
- одна длинная пауза на прогон, а не рваная прокрутка. Похоже на пересоздание swapchain при разворачивании окна (прототип создаёт окно 1920×1080 и сразу `Maximized`) или на то, что окно в этот момент перекрыто или не в фокусе. Во время части прогонов владелец работал за машиной, это могло влиять.

**Что сделать:** воспроизвести на спокойной машине с явно видимым окном. Если повторится — трассировка (`perf`, логи blade/GPUI) и патч или issue в GPUI.

### 2. Старт workbench с папкой на NTFS-FUSE: 1,1–2,4 с

`kumiko <папка>` вызывает `CoreApi::open_folder` синхронно **до** открытия окна (`app/kumiko/src/main.rs`, `runtime.block_on`). Внутри `open_folder` ставится рекурсивный inotify-watch (`kumiko-fs/src/watcher.rs`, `RecursiveMode::Recursive`) на все каталоги, включая `target/`: в репозитории 2 803 каталога, без `target/` — 353. На ext4 (копия без `target/`) старт 144–179 мс, на NTFS через FUSE — 1,1–2,4 с.

**Что сделать:**
- открывать окно до `open_folder` или ставить watch в фоне, чтобы дерево появлялось сразу;
- исключать `target/`, `.git/` и т. п. из watch;
- перемерить на ext4 с полным репозиторием (с `target/`), чтобы отделить влияние FUSE от числа каталогов.

### 3. RAM в покое: +90 МБ от библиотек NVIDIA

| Вариант | RSS | Anon | File-backed |
|---|---|---|---|
| Прототип, по умолчанию | 154 МБ | 53 МБ | 104 МБ |
| Прототип, только Intel ICD | 64 МБ | 35 МБ | 29 МБ |
| Прототип, только NVIDIA ICD | 311 МБ | 103 МБ | 208 МБ |
| Workbench, по умолчанию | 146 МБ | 39 МБ | 107 МБ |
| Workbench, только Intel ICD | 51 МБ | 20 МБ | 31 МБ |

Рисует Intel, но загрузчик Vulkan при перечислении адаптеров подгружает драйвер NVIDIA: +~90 МБ, в основном file-backed (разделяемые `.so`, PSS заметно меньше RSS). На машине только со встроенной графикой бюджет < 120 МБ выполняется с запасом. На гибридной машине RSS по умолчанию его превышает.

**Что решить:** либо считать бюджет по PSS или anon (фактическая цена процесса), либо после выбора адаптера не держать чужие ICD. Второе — вопрос к blade/GPUI.

### 4. CPU в покое у прототипа 9–21 %

Главный поток прототипа просыпается ~60 раз в секунду (`strace`: 1 560 `epoll_pwait` и `timerfd_settime` за 25 с, ~47 000 `ioctl` к GPU), то есть рисует кадр на каждый vsync без изменений. У workbench этого нет: 0,70–0,83 %, бюджет выполняется. Значит, причина в прототипе (скорее всего `a11y-bridge` или `uniform_list` в режиме без бенчмарка), а не в GPUI. Для продукта не блокер, для точности будущих замеров на прототипе стоит поправить.

### 5. Wayland

Нативный Wayland-сеанс не проверялся: машина работает в X11-сеансе. Во вложенном `gnome-shell --nested --wayland` (GNOME 46):
- прототип стартует без паники `UnsupportedVersion` из WSLg: 584–1 255 мс, вложенный композитор добавляет накладные расходы, цифры ориентировочные;
- прокрутка 58,9 fps, p95 17,1 мс;
- workbench открылся и проработал 8 с без ошибок.

Мелкая находка: в режиме `start` под Wayland прототип печатает отчёт дважды. `finish` вызывается повторно до выхода по `cx.quit()`.

**Что сделать:** войти в сеанс «Ubuntu» (Wayland) на экране входа и повторить разделы «Прокрутка», «Старт», «RAM», «CPU».

### 6. Прочее

- Окно workbench на X11 без `WM_CLASS` (в `xwininfo` — `"Kumiko": ()`). GNOME не сможет связать окно с `.desktop`-файлом и иконкой. Надо задать `app_id` в `WindowOptions`.
- `iced-proto` в спайке больше не собирается: `naga 27.0.3` не компилируется с `codespan-reporting 0.12.0` из lock-файла (`String: WriteColor`). Запасной вариант ADR-003 сейчас не собрать без обновления lock-файла спайка.

## Что осталось сделать (для приёмки E7)

1. **IME (ibus):** проверить руками, когда в workbench появится поле ввода или редактор. Нужны русская раскладка и ввод через IBus (например, `ibus-anthy` или `ibus-pinyin`), окно предредактирования у курсора.
2. **Нативный Wayland-сеанс:** повторить замеры (п. 5).
3. **Подвисания X11:** воспроизвести и разобрать (п. 1).
4. **Клавиша → пиксель на Linux:** нужен аналог `latency-probe` (X11: XTest + XGetImage; Wayland — только фотодатчик). Отложено ADR-003 до E8/E14.
5. **Решение по бюджету RAM на гибридной графике** (п. 3).
6. **Старт с проектом:** не блокировать окно на `open_folder` (п. 2).

## Воспроизведение

```bash
# Прототип (из spikes/ui)
cargo build --release -p gpui-proto
R=$PWD/target/linux/report.jsonl
for b in start scroll type; do
  SPIKE_BENCH=$b SPIKE_LABEL=linux-x11 SPIKE_REPORT=$R \
  SPIKE_T0=$(($(date +%s%N)/1000)) ./target/release/gpui-proto | tail -1
done
# Только Intel: добавить VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/intel_icd.json
# HiDPI 2x на X11: GPUI_X11_SCALE_FACTOR=2

# RAM и CPU в покое (любой из бинарников)
./target/release/gpui-proto & P=$!; sleep 30
grep -E 'VmRSS|RssAnon|RssFile' /proc/$P/status
c1=$(awk '{print $14+$15}' /proc/$P/stat); sleep 60; c2=$(awk '{print $14+$15}' /proc/$P/stat)
echo "cpu%: $(echo "scale=2;($c2-$c1)/60" | bc)"; kill $P

# Вложенный Wayland
dbus-run-session -- gnome-shell --nested --wayland --wayland-display=wayland-kmk &
WAYLAND_DISPLAY=wayland-kmk env -u DISPLAY SPIKE_BENCH=scroll ./target/release/gpui-proto

# AT-SPI: включить доступность, обойти дерево через gi.repository.Atspi, выключить обратно
gsettings set org.gnome.desktop.interface toolkit-accessibility true
```
