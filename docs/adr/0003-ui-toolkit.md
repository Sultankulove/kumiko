# ADR-003. UI-тулкит

- Статус: Accepted с условиями (решение владельца по итогам спайка E6, 26.09.2026)
- Дата: 2026-09-23, решение 2026-09-26
- Источник: ТЗ v1.0 ([docs/spec/kumiko-tz-v1.0.md](../spec/kumiko-tz-v1.0.md)), разделы 20, 23; [ADR-020](0020-windows-in-mvp.md); отчёт спайка [docs/research/ui-spike.md](../research/ui-spike.md)

## Контекст

Rust GUI-тулкиты различаются зрелостью IME, доступности и производительности; ошибка выбора дорого стоит (ТЗ, разделы 20, 24). После ADR-020 тулкит обязан работать нативно и на Windows.

## Рассмотренные варианты

- iced 0.14 (MIT, wgpu, текст на cosmic-text).
- GPUI 0.2.2 (тулкит Zed, Apache-2.0; на Windows DirectX и DirectWrite, на Linux blade/Vulkan и cosmic-text).
- gtk4-rs (LGPL, динамическая линковка) — запасной; выбывает из-за ADR-020 (на Windows нужен MSYS2-рантайм) и самой медленной прокрутки в замерах.
- Исключены заранее: Tauri/Electron, Slint (лицензия), egui (immediate mode).

## Замеры (кратко)

Windows 11, встроенная Intel UHD, 1920×1200 при 125%, 165 Гц:

| | iced | GPUI | Порог |
|---|---|---|---|
| Прокрутка 10 000 строк | 162 fps | 160 fps | ≥ 60 |
| Клавиша → пиксель, p95 (верхняя оценка с DWM) | 29 мс | 24 мс (p50 12,6) | < 16 |
| Холодный старт | 1,5–2,4 с | ~190 мс | < 300 мс |
| RAM в покое | 242 МБ | 89 МБ | < 120 МБ |
| Доступность через AccessKit без форка | да | да | да |
| IME | API | API, опробован в Zed | работает |

Подробности, методика и данные Linux (WSLg) — в [отчёте спайка](../research/ui-spike.md).

## Решение

UI-слой (L1) строится на **GPUI** при следующих условиях.

1. **Версия** закрепляется точно (`=0.2.x` или git-ревизия) и обновляется только отдельным изменением с прогоном замеров спайка.
2. **Изоляция.** GPUI используется только в UI-крейтах L1 (`kumiko-ui`, `kumiko-editor-view`, `kumiko-terminal-view`). Архитектурный тест запрещает GPUI во всех остальных крейтах. Ядро, сервисы и плагины о тулките не знают, как и раньше.
3. **Текст редактора и терминала.** Поправка к ТЗ (раздел 20, «рисуются собственным виджетом на cosmic-text»): виджеты остаются нашими, но текст шейпится и рисуется текстовой системой GPUI. На Linux это cosmic-text, на Windows — DirectWrite. Модель документа, позиции (UTF-8), подсветка и раскладка строк остаются в наших крейтах.
4. **Доступность:** AccessKit подключается снаружи. На Windows — `SubclassingAdapter` на окно, созданное скрытым (`show: false`) и показанное после подключения. На Linux — `accesskit_unix`. Дерево доступности строит наш UI-слой из своей модели виджетов.
5. **Linux перемеряется до приёмки E7** на нативной системе (GNOME/Wayland и X11, встроенная графика): прокрутка, старт, память, IME через ibus или fcitx, AT-SPI. Известные проблемы GPUI 0.2.2 чинятся патчами:
   - паника на `UnsupportedVersion` под старым Wayland-композитором;
   - `unimplemented!` в `window_handle()` под X11.

   Патчи идут в upstream, а до принятия — через `[patch]` или форк: Apache-2.0 это позволяет.
6. **Клавиша → пиксель.** Точный замер без DWM и шага опроса (фотодатчик или таймстемпы кадров) — в бюджетах E8 и E14. Верхняя оценка спайка (p95 24 мс) принимается как допустимая для E7.

## Последствия

- UI-крейты перестают быть заглушками начиная с E7. Прототип `spikes/ui/gpui-proto` — отправная точка для workbench.
- Сборка UI на Windows требует MSVC Build Tools. Переменная `CC=clang` при отсутствующем clang ломает сборку `ring`.
- Дерево зависимостей растёт примерно до 675 крейтов. Лицензии совместимы, cargo-deny для UI-крейтов проверяется в E7.
- Если условие 5 не выполнится (GPUI на нативном Linux не проходит пороги или требует несоразмерных патчей), решение пересматривается, запасной вариант — iced. Спайк и измерительный стенд остаются в репозитории для повторных замеров.
