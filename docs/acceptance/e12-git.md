# Приёмка E12: Git-плагин

Этап E12 (ТЗ, раздел 28): WASM-плагин `kumiko.git` на системном `git`, декларативный UI, интерфейс `kumiko.git.repository`. Критерий MVP 13, «отключение плагина не ломает дерево файлов», фикстура-потребитель интерфейса.

## Автоматически

`tests/headless/e12_git.rs` на настоящем репозитории: `git status` (ветка, изменённые и неотслеживаемые файлы), вид Commit, цвета файлов и ветка в строке статуса, commit, новая ветка, интерфейс `kumiko.git.repository` из другого плагина (`kumiko.echo`), отключение плагина убирает его UI, индекс файлов работает. Модульные тесты плагина: разбор `status --porcelain=v2 -z`, URI и дерево вида.

## Вручную

Плагин ставится в каталог плагинов пользователя (`plugin.toml` и `plugin.wasm`, собранный `cargo build -p kumiko-git --release --target wasm32-wasip2`), до kits в E13.

| № | Действие | Ожидается |
|---|---|---|
| 1 | Открыть папку с git-репозиторием, `Alt+0` | Окно «Commit»: «Changes» и «Unversioned Files» с файлами, цвета как в IntelliJ (изменён — синий, неотслеживаемый — красный). В строке статуса `⎇ main`. |
| 2 | Дерево проекта | Имена изменённых файлов окрашены. |
| 3 | Щелчок по файлу в окне | Файл открывается. |
| 4 | Палитра: «Git: Commit…» (`Ctrl+K`) | Запрос сообщения, после `Enter` изменения отслеживаемых файлов закоммичены, вид обновился. |
| 5 | «Git: Checkout Branch…», «Git: New Branch…» | Выбор ветки и запрос имени, ветка меняется в строке статуса. |
| 6 | «Git: Pull» (`Ctrl+T`), «Git: Push» (`Ctrl+Shift+K`) | Ответ git в сообщении строки статуса. |
| 7 | Отключить плагин | Цвета и вид исчезают, дерево проекта работает. |

На Windows вживую пройдены шаги 1–3 (2026-10-17). Commit, ветки, pull и push проверены headless (commit, ветка) или только кодом (pull, push). Linux — за владельцем.

## Отложено

- Просмотр diff (read-only документ `git:`, diff view): команда `git.diff` возвращает текст, окна нет.
- Дерево Branches и History.
- `GIT_ASKPASS` для паролей: работают системные credential helpers, запрос пароля не встроен.
- Выбор файлов для коммита галочками (сейчас коммитятся все отслеживаемые изменения, как `commit -a`).
- Окрашивание каталогов с изменениями.
