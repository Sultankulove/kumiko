# Приёмка E7: ручной сценарий workbench

Этап E7 (ТЗ, раздел 28) принимается ручным сценарием, скриншот-тестом раскладки и правилом «все действия — команды». Сценарий проходится на **Windows и Linux** (ADR-020).

Скриншот-тест раскладки автоматический: `crates/kumiko-ui/src/layout.rs`, тест `default_layout_snapshot` и соседние. Он проверяет геометрию областей для заданного размера окна без запуска GPUI.

## Подготовка

```bash
cargo build --release -p kumiko
```

Запуск — `target/release/kumiko <папка проекта>`. Встроенные ресурсы берутся из `resources/` рядом с бинарником или из дерева исходников; путь можно задать в `KUMIKO_RESOURCES`. Журнал пишется в stderr и в окно Output, канал «IDE Log». Уровень задаёт `KUMIKO_LOG`.

## Сценарий

Сочетания клавиш — из keymap по умолчанию (`resources/keymaps/default`).

| № | Действие | Ожидается |
|---|---|---|
| 1 | Запустить `kumiko <папка>` | Окно открывается сразу, не дожидаясь папки. Раскладка Classic UI: меню, тулбар, полоски tool-window, окно «Project», строка статуса. Тема Darcula. В журнале строка `first frame N ms after start`. |
| 2 | Дождаться дерева | В «Project» папка раскрыта, сначала каталоги, потом файлы. `.git` скрыт через `files.exclude`. **Критерий MVP 3.** |
| 3 | Стрелками пройти по дереву: `→` раскрывает каталог или входит в него, `←` сворачивает или идёт к родителю, `Enter` на файле открывает его | Файл открывается во вкладке только для чтения, с номерами строк. В тулбаре путь `проект › каталог › файл`. В строке статуса число строк, окончания строк и кодировка. |
| 4 | `Ctrl+Shift+N` (или `Ctrl+P`), набрать часть имени файла | Всплывающее окно Quick Open, совпавшие буквы подсвечены. `Enter` открывает файл. С пустым вводом сверху недавние файлы. |
| 5 | `Ctrl+Shift+A` (или `Ctrl+Shift+P`), набрать `tab` | Палитра команд: команды со своими сочетаниями. `Enter` выполняет выбранную. |
| 6 | `Ctrl+G`, набрать номер строки, `Enter` | Файл прокручивается к строке. |
| 7 | Меню View → Split Right, затем открыть другой файл | Область редактора делится на две группы. Файл открывается в активной группе; её вкладка подчёркнута акцентным цветом. |
| 8 | `Ctrl+F4` в одной из групп до последней вкладки | Опустевшая вторая группа исчезает. |
| 9 | `Alt+6`, затем палитра → «Output Tool Window» | Внизу «Problems» (без проблем — «No problems») и «Output» с каналом «IDE Log». |
| 10 | `Alt+1` три раза | Окно «Project» получает фокус, затем скрывается, затем снова открывается. `Esc` в дереве возвращает фокус в редактор. |
| 11 | Меню Tools → Select Theme…, выбрать Hinoki Dark, потом Darcula | Тема меняется сразу, без перезапуска. Выбор записывается в пользовательские настройки. |
| 12 | Закрыть окно (крестик или `Ctrl+Q`), запустить снова с той же папкой | Процесс завершается. При новом запуске восстанавливаются раскладка, вкладки обеих групп, split и недавние файлы (`<state>/workspaces/<hash>.json`). |
| 13 | Поставить `"workbench.locale" = "ru"` в пользовательских настройках | Меню, заголовки окон и команд — по-русски. |
| 14 | Экранный диктор (Windows) или Orca / Accerciser (Linux) | Видны меню, тулбар, дерево проекта с элементами, список вкладок, документ, строка статуса. Фокус дерева следует за выделением. |

## Все действия — команды

Всё, что делает пользователь в workbench, вызывается как команда Command Service. Поэтому любое действие достаётся из keymap, палитры и `contributes.menus` плагинов (`location = "menu/<имя>"`).

| Команда | Действие |
|---|---|
| `workbench.toggleProject` / `toggleProblems` / `toggleOutput` | Tool windows |
| `workbench.openFile [uri]`, `closeEditor`, `nextEditor`, `previousEditor` | Вкладки |
| `workbench.quickOpen`, `showCommands`, `gotoLine` | Quick Open |
| `workbench.splitRight`, `splitDown`, `unsplit` | Split |
| `workbench.selectTheme`, `setTheme [id]` | Темы |
| `workbench.quit` | Выход |

Правка текста, IME и подсветка приходят в E8 вместе с редактором.
