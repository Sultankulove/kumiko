# ADR-001. Модель процессов и уровни L0–L3

- Статус: Accepted
- Дата: 2026-09-23
- Источник: ТЗ v1.0 ([docs/spec/kumiko-tz-v1.0.md](../spec/kumiko-tz-v1.0.md))

## Контекст

Исходная концепция «все плагины в отдельных процессах» противоречила заменяемому редактору: клавиша через IPC добавляет задержку и джиттер (P1, P15, P17).

## Рассмотренные варианты

- Всё, включая редактор, — плагины в отдельных процессах.
- Один процесс, всё in-process с нативными плагинами (`.so`).
- Уровни: L0 ядро и L1 UI in-process, L2 изолированные расширения (WASM in-process или процесс), L3 данные.

## Решение

Третий вариант (ТЗ, раздел 8). L0 не зависит от L1/L2; L1 получает всё через `CoreApi`; L2 — только через KPP. Падение L2 не завершает главный процесс; WASM-плагины не исполняются в UI-потоке. L1 заменяется на этапе сборки.

## Последствия

Задержка ввода не зависит от IPC. L1 в MVP нельзя заменить в рантайме (см. ADR-013, ADR-018). Граница уровней проверяется `tests/architecture.rs`.
